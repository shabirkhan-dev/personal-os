## What

Roadmap item: photos of pieces, meals and dreams stayed on the phone, so a new phone got the
records without their photos.

## Proposal or Ask

No API change: the existing `media` upload (presigned PUT, then confirm) is reused. After each
sync while signed in, `usePhotoSync` uploads every `file://` photo in `PHOTO_TARGETS` (pieces,
To buy items, meals, dreams, owned things) and points the record at the R2 link, re-reading it
first so a photo changed meanwhile is left alone. The local file moves to `synced-photos/` under
its R2 name and `photoSource` shows it, so the uploading phone keeps working offline.

## Validation

- 3 new tests in `photo-sync.test.ts` against the in-memory record store.
- Not run against a real R2 bucket or on a device.

## Resolution

Landed on `ccr-cdb9b079-navb5d`. Follow-ups: a replaced photo leaves its old R2 object behind
(deleted with the account); HEIC photos are not uploadable (the API accepts JPEG, PNG, WebP, GIF)
and are retried each sync.
