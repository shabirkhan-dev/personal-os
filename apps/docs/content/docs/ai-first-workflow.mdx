---
title: AI-First Workflow
description: How humans and coding agents can move quickly without losing project truth.
---

AI is part of the development workflow and a future product capability. In both cases, it should
make reasoning more visible, not make ownership or verification disappear.

## What agents must read

Before an agent changes code, it should read:

1. Root `AGENTS.md` and any app-specific instructions.
2. The relevant source of truth: the [production roadmap](/docs/production-roadmap),
   `DESIGN.md`, or the [API status board](/docs/backend-api).
3. `.agents/README.md` and the team's notes when the work crosses ownership boundaries.
4. Installed framework documentation for framework-sensitive work. For Next.js, use the docs under
   `node_modules/next/dist/docs/` as required by the repository rules.

Agents should inspect the current tree before proposing a new abstraction. A plausible pattern from
another project is not evidence that Personal OS needs it.

## A safe agent loop

```text
Read rules → inspect code → state scope → make a focused change
→ run targeted checks → review the diff → update source-of-truth docs
→ hand off evidence and remaining risks
```

For cross-team work, raise a board card before editing another team's area. Do not write to another
team's notes file. Keep contracts in the API status board, not in duplicated prompts or tickets.

## Review standards for generated code

- Prefer small, named functions and explicit types over clever compression.
- Reject `any`, silent catches, unchecked user input, and unbounded queries.
- Check authorization and ownership independently of UI visibility.
- Check timezone and date semantics for every daily or monthly feature.
- Reuse the existing UI tokens and primitives; do not introduce a second design language.
- Test empty, loading, error, retry, and narrow-screen states for user-facing flows.
- Explain environment-limited checks instead of reporting them as passing.

## Product AI boundary

The public path is:

```text
Web / Mobile → NestJS AI proxy → apps/ai-api → model provider
```

`apps/ai-api` is an internal beta service. Nest owns authentication, authorization, request shape,
provider policy, and secret handling. AI output is untrusted until validated and should be presented
as a suggestion, draft, or explanation. It should not silently create a transaction, change a routine,
or send a message.

## Prompts and data minimization

- Send only the fields needed for the task.
- State the user's timezone when a date or schedule is involved.
- Prefer structured output validated by a schema.
- Keep user intent and confirmation outside the model response.
- Make it possible to inspect, correct, regenerate, or discard a suggestion.
- Never place secrets, raw access tokens, or unnecessary personal data into prompts or logs.

## Done means evidence

An AI-assisted change is ready for review when the author can point to the files changed, the
commands run, the behavior checked, and the remaining uncertainty. A good agent leaves the next
developer with less archaeology, not more.
