How code is organized inside each app, and which rules are enforced by scripts rather than
convention. For how the pieces fit together at runtime, see
[Product System Design](/docs/product-system-design).

## Principles

- Keep apps thin at the edges: screens and controllers compose, logic lives below them.
- Pure logic is plain TypeScript with tests (`lib/` in mobile, services in the API).
- Reusable, app-agnostic code goes in `packages/*`.
- Enforce boundaries with checks, not only conventions.

## Layering

### `apps/mobile`

- `src/app/*` is Expo Router: routing and screen composition only.
- `src/modules/<name>/` is one feature: `components`, `hooks`, `lib` (pure logic and parsing,
  unit-tested), `services` (device and network I/O) and `store` (Zustand, usually a document store).
- `src/lib/*` holds app-wide helpers: the API client, the record store (`lib/db`), sync
  (`lib/sync`), storage, dates.
- `src/components/*` and `src/theme/*` hold Kit v2 components and the theme provider. Screens use
  `@personal-os/tokens` through the theme; no raw colour values.

### `apps/api`

- `src/modules/<name>/` is one feature: `<name>.routes.ts` (Hono routes, validation, `ok()`),
  `<name>.service.ts` (logic), `<name>.repository.ts` (Drizzle queries), `<name>.schema.ts` (zod
  and response types).
- `src/config/` holds the typed environment (`env.ts`), fixed settings (`settings.ts`) and the
  error and message table (`messages.ts`).
- `src/core/` holds the cross-cutting pieces: `AppError`, the response envelope, the error
  handler, validation, rate limiting and the request context.
- `src/db/` holds the Drizzle schema, the per-request client and the committed migrations.
- Routes stay thin; services hold the logic; repositories hold the queries. Errors are thrown as
  `AppError("CODE")`, never written inline.

### `packages/*`

- Packages never import app aliases like `@/...`.
- Each package exposes a public entrypoint (`src/index.ts`).

## Enforcement

`bun run architecture:check` runs locally (Lefthook) and in CI. It fails on:

- `@/...` imports inside `packages/*`
- cross-app relative imports (`../../apps/...`)
- file or folder names under TS/JS `src/` that are not kebab-case (dotted names like
  `auth.service.ts`, route groups like `(home)` and `[id]` params are allowed)
