## How to call the API

### Auth

- All endpoints below require `Authorization: Bearer <accessToken>` unless noted.
- Access tokens are short-lived. On `401`, call `POST /auth/refresh` (cookie-based)
  to get a new session — see `/docs` Swagger page on the API server for auth endpoints.
- Sessions also set httpOnly cookies; browser clients use `credentials: "include"`.

### Response envelope

Every JSON response is wrapped by the API:

```jsonc
// success
{ "success": true, "statusCode": 200, "data": { /* payload */ } }
// failure
{ "success": false, "statusCode": 400, "code": "VALIDATION_ERROR", "message": "...", "errors": [{ "path": "name", "message": "..." }] }
```

Frontend API clients unwrap `data` automatically (web: `src/lib/api/client.ts`,
mobile: `src/lib/api/client.ts`).

### Conventions

- URI-versioned (`/api/v1`). Breaking changes ship as `/api/v2` or are listed as
  **BREAKING** in the changelog with migration notes.
- Dates sent/stored per user timezone come from `user_profiles.timezone`
  (fallback `UTC`) as `YYYY-MM-DD`.
- Weekdays are ISO numbers: `1 = Monday … 7 = Sunday`.

## Routines API (ready)

A routine belongs to one user and contains ordered items ("steps").
Completions are logged **per item per day** — a routine counts as done when all
its items are done for the day.

### Types

```ts
type RoutineScheduleType = "daily" | "specific_days";

interface Routine {
	id: string; // uuid
	name: string;
	description: string | null;
	scheduleType: RoutineScheduleType;
	daysOfWeek: number[]; // [] for daily; e.g. [1, 3, 5]
	archivedAt: string | null;
	createdAt: string;
	updatedAt: string;
	items: Array<{
		id: string;
		name: string;
		notes: string | null;
		targetTime: string | null; // "HH:MM"
		sortOrder: number;
	}>;
}

interface TodayView {
	date: string; // "YYYY-MM-DD" in the user's timezone
	timeZone: string;
	weekday: number; // ISO weekday of `date`
	routines: Array<{
		id: string;
		name: string;
		description: string | null;
		completedItems: number;
		totalItems: number;
		items: Array<{
			id: string;
			name: string;
			targetTime: string | null;
			sortOrder: number;
			completed: boolean;
		}>;
	}>;
}
```

### Endpoints

All routes are prefixed `/routines` and require auth.

| Method | Path | Purpose | Returns |
| --- | --- | --- | --- |
| GET | `/routines/today` | Scheduled routines for today + completion state | `TodayView` |
| GET | `/routines?limit=&offset=` | List active routines (bounded) | `Routine[]` |
| GET | `/routines/:id` | Single routine | `Routine` |
| POST | `/routines` | Create routine with items | `Routine` (201) |
| PATCH | `/routines/:id` | Update fields; `items` replaces all active items | `Routine` |
| DELETE | `/routines/:id` | Soft-archive (history preserved) | `{ id, archived: true }` |
| POST | `/routines/:routineId/items/:itemId/toggle` | Toggle item completion for today | `{ itemId, date, completed }` |

#### Query params for `GET /routines`

| Param | Type | Default | Rules |
| --- | --- | --- | --- |
| `limit` | int | 100 | 1–200 |
| `offset` | int | 0 | ≥ 0 |

Malformed uuids in paths return `400 VALIDATION_ERROR` (never a DB hit).
Unknown ids return `404 NOT_FOUND`.

#### Create/update body examples

```jsonc
// POST /routines
{
	"name": "Morning routine",
	"description": "Start the day right",
	"scheduleType": "specific_days",
	"daysOfWeek": [1, 3, 5],
	"items": [
		{ "name": "Drink water", "targetTime": "07:00" },
		{ "name": "Stretch" }
	]
}

// PATCH /routines/:id — partial; "archived": false un-archives
{
	"name": "Morning ritual",
	"items": [{ "name": "Meditate" }]
}
```

Rules enforced server-side:

- `name` required (1–120 chars); `description` ≤ 500; ≤ 50 items; item names 1–200.
- `scheduleType: "specific_days"` requires non-empty `daysOfWeek`.
- `targetTime` must be `"HH:MM"` (24h).
- Toggling is day-scoped and idempotent-safe (unique index on user+item+day).

## Finance API (ready)

Money is stored as **integer minor units** (`amountMinor`: paise for INR) —
never floats. Dates (`occurredOn`, `YYYY-MM-DD`) are supplied by the client so
grouping matches the user's local day. Categories are free-form strings that
the server **trims and lower-cases**, so `Food` and `food` always group together.
Uncategorized expenses appear under the `uncategorized` key in summaries.

### Types

```ts
type TransactionType = "expense" | "income";

interface FinanceTransaction {
	id: string; // uuid
	type: TransactionType;
	amountMinor: number; // integer, >= 1
	currency: string; // default "INR"
	category: string | null;
	note: string | null;
	occurredOn: string; // "YYYY-MM-DD"
	createdAt: string;
	updatedAt: string;
}

interface FinanceBudget {
	id: string;
	month: string; // "YYYY-MM"
	category: string;
	limitMinor: number;
}

interface MonthSummary {
	month: string;
	incomeTotal: number;
	expenseTotal: number;
	netTotal: number; // income - expense
	categories: Array<{
		category: string;
		spent: number; // expense sum for the month
		limit: number | null; // budget limit, if set
	}>;
}
```

### Endpoints (all under `/finance`, auth required)

| Method | Path | Purpose | Returns |
| --- | --- | --- | --- |
| GET | `/finance/transactions?limit=&offset=&type=&category=&month=` | Filterable, bounded list (newest first) | `FinanceTransaction[]` |
| POST | `/finance/transactions` | Create; `occurredOn` defaults to today (user tz) | `FinanceTransaction` (201) |
| PATCH | `/finance/transactions/:id` | Partial update | `FinanceTransaction` |
| DELETE | `/finance/transactions/:id` | **Hard delete** (ledger semantics, unlike routines) | `{ id, deleted: true }` |
| GET | `/finance/summary/:month` | Totals + per-category spend + budget vs actual | `MonthSummary` |
| PUT | `/finance/budgets/:month` | Replace the month's whole budget set | `FinanceBudget[]` |
| GET | `/finance/budgets/:month` | List budgets for a month | `FinanceBudget[]` |

#### Validation rules

- `month` must match `YYYY-MM`; invalid values return `400 VALIDATION_ERROR`.
- `occurredOn` must be a real calendar date between 2000 and 2100.
- `amountMinor` / `limitMinor`: integers ≥ 1 (budgets allow 0), capped at 10¹².
- `category`: 1–64 chars after trim/lower-case; letters, digits, space, `_`, `-`.
- List query: `limit` 1–200 (default 100), `offset` ≥ 0; filters combine with AND.

#### Body examples

```jsonc
// POST /finance/transactions
{ "type": "expense", "amountMinor": 25000, "category": "Groceries", "note": "Weekly market run" }

// PUT /finance/budgets/2026-09  (replaces all budgets for September)
{
	"budgets": [
		{ "category": "food", "limitMinor": 1500000 },
		{ "category": "transport", "limitMinor": 400000 }
	]
}
```

## Changelog

### 2026-08-24 — Observability, timeouts, production config hardening

- External calls are now deadline-bounded: `EXTERNAL_REQUEST_TIMEOUT_MS`
  (default 10s) applies to Resend email, the AI service, and the Stripe/Razorpay
  SDKs. Timeouts surface as stable 503s (`EMAIL_PROVIDER_TIMEOUT`,
  `AI_UNAVAILABLE`) — no silent hangs.
- Structured request logging: successful requests and 5xx/unexpected errors are
  logged with `method path status durationMs requestId`; inbound request IDs are
  sanitized; `/health` and `/docs` are excluded; no secrets/bodies are logged.
- Production boot now fails closed on localhost/default DB, CORS, WebAuthn, and
  email-sender values, and requires `DATABASE_SSL=true` unless a managed host.
- OpenAPI (`/api/docs`) is now gated by `SWAGGER_ENABLED` and **disabled by
  default in production**.

### 2026-08-23 — Finance v1 shipped

- New module under `/finance`: transactions CRUD, monthly budgets (PUT replaces
  the month's set), and `GET /finance/summary/:month`.
- Money is integer minor units; categories are server-normalized
  (trim + lower-case). See the Finance section for full contracts.
- No frontend consumers yet — shape changes are still cheap, request them via a
  board card.

### 2026-08-23 — Routines v1 hardening

- `GET /routines` now validates `limit` (1–200, default 100) and `offset` (≥ 0).
  Response shape unchanged (still `Routine[]`).
- Malformed uuid path params now fail fast with `400 VALIDATION_ERROR`.
- Routine creation and item replacement are now atomic (DB transaction):
  clients will never observe a routine without its items after a success response.
- Schedule/date helpers extracted to `routines.schedule.ts` (internal refactor,
  no contract change).

### 2026-08-23 — Routines v1 shipped

- Initial release of everything in the table above. Consumers: web + mobile Today
  screens.
