Where each piece of Personal OS runs in production:

| App | Platform | Notes |
|-----|----------|--------|
| `apps/mobile` | [EAS](https://expo.dev/eas) | Builds and over-the-air updates; see `apps/mobile/README.md` |
| `apps/web` | [Cloudflare Workers](https://workers.cloudflare.com) | Next.js static export served as Worker assets + `/api/notify` |
| `apps/docs` | [Vercel](https://vercel.com) | Separate Vercel project |
| `apps/nest-api` | [Render](https://render.com) | Docker Blueprint + Neon `DATABASE_URL` |
| `apps/ai-api` | [Render](https://render.com) | Same Blueprint; only the Nest API calls it |
| Database | [Neon](https://neon.tech) | Serverless Postgres (TLS auto-detected) |

Repo files: `apps/web/README.md`, `apps/docs/vercel.json`, root `render.yaml`.

## 1) Neon database

1. Create a project at [console.neon.tech](https://console.neon.tech).
2. Copy the **pooled** connection string (includes `sslmode=require`).
3. You will paste it into Render as `DATABASE_URL`. Nest enables TLS automatically for `neon.tech` URLs.

## 2) Nest API and AI service on Render

The root `render.yaml` creates both services: `personal-os-api` (Nest) and `personal-os-ai`
(FastAPI). The phone only talks to the API; the API calls the AI service with a shared token that
Render generates on the AI service and copies to the API.

1. In Render, **New → Blueprint**, connect this GitHub repo and pick `render.yaml`.
2. Fill the **sync: false** values when Render asks:

| Service | Variable | Value |
|---------|----------|-------|
| API | `DATABASE_URL` | Neon pooled URL |
| API | `RESEND_API_KEY` | `re_...` from [Resend](https://resend.com); sign-in codes go out by email |
| API | `AUTH_EMAIL_FROM` | `Personal OS <noreply@your-domain.com>` (a verified Resend domain) |
| API | `AI_API_URL` | The AI service's URL, e.g. `https://personal-os-ai.onrender.com`. Leave it empty on the first run and fill it once the AI service exists |
| AI | `OPENAI_API_KEY` | Your provider key |
| API | `WEB_APP_URL`, `CORS_ORIGIN`, `WEBAUTHN_*` | Only for browser clients and passkeys; leave empty for now |

The Blueprint generates `JWT_SECRET`, `AUTH_TOKEN_SECRET` and `AI_SERVICE_TOKEN`, and sets the
AI service to `AI_PROVIDER=openai_compatible` with `gpt-4o-mini`. Any OpenAI-compatible provider
works: change `OPENAI_BASE_URL` and `OPENAI_MODEL` on the AI service.

3. Confirm both are up:

```bash
curl -sS https://<api>.onrender.com/api/v1/health
curl -sS https://<ai>.onrender.com/api/v1/health   # "provider": "openai_compatible"
```

Migrations run on container start when `RUN_MIGRATIONS=true` (set in the Blueprint). Changing a
key never needs an app rebuild: update it in Render and the service restarts.

**Note:** free Render services sleep when idle; the first request takes about 30 s to wake them,
and the app gives up after 15 s, so the first try after a quiet spell can fail once.

## 3) The app on EAS

1. On expo.dev, open the project → **Settings → GitHub**, connect this repo, base directory
   `apps/mobile`.
2. **Environment variables**: add `EXPO_PUBLIC_NEST_API_URL=https://<api>.onrender.com` (no
   path) to every environment. It is baked in at build time, so add it before building.
3. Build from the GitHub tab, or `bunx eas-cli build --profile preview --platform android` for a
   standalone APK that talks to the hosted API.

## 4) Landing page on Cloudflare Workers

`apps/web` is a static export (`out/`) served as Worker static assets, plus a small Worker for
launch-day sign-ups (`/api/notify`, Workers KV). It does not call Nest.

1. **Workers & Pages → Create → Workers → Import a repository**, this repo, branch `main`.
2. Root directory `apps/web`, build command `bun run build`, deploy command `npx wrangler deploy`.
3. Create a KV namespace and put its id in `apps/web/wrangler.jsonc` (`WAITLIST` binding).
4. Add a custom domain, for example `personalos.rabtx.dev`.

Full steps: `apps/web/README.md`.

## 5) Docs on Vercel

1. **Add another project** from the same repo.
2. **Root Directory:** `apps/docs`.
3. Env (optional, for docs AI chat):

| Variable | Value |
|----------|--------|
| `OPENROUTER_API_KEY` | from [OpenRouter](https://openrouter.ai) |
| `OPENROUTER_MODEL` | e.g. `anthropic/claude-3.5-sonnet` |

4. Deploy. Docs do not call Nest.

## Sessions and cookies

The mobile app sends `X-Client-Platform: native`, receives its refresh token in the response body
and stores it in SecureStore, so it needs no cookies and no CORS. Cookie settings
(`COOKIE_SAME_SITE`, `Secure`, `COOKIE_DOMAIN`) only matter for a browser client, and there is
none today: the landing page and docs never call the API.

- [ ] Landing page live on its custom domain, waitlist KV bound
- [ ] Docs project live (optional OpenRouter)
