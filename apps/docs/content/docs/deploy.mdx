Where each piece of Personal OS runs in production:

| App | Platform | Notes |
|-----|----------|--------|
| `apps/mobile` | [EAS](https://expo.dev/eas) | Builds and over-the-air updates; see `apps/mobile/README.md` |
| `apps/web` | [Cloudflare Workers](https://workers.cloudflare.com) | Next.js static export served as Worker assets + `/api/notify` |
| `apps/docs` | [Vercel](https://vercel.com) | Separate Vercel project |
| `apps/nest-api` | [Render](https://render.com) | Docker Blueprint + Neon `DATABASE_URL` |
| Database | [Neon](https://neon.tech) | Serverless Postgres (TLS auto-detected) |

Repo files: `apps/web/README.md`, `apps/docs/vercel.json`, root `render.yaml`.

## 1) Neon database

1. Create a project at [console.neon.tech](https://console.neon.tech).
2. Copy the **pooled** connection string (includes `sslmode=require`).
3. You will paste it into Render as `DATABASE_URL`. Nest enables TLS automatically for `neon.tech` URLs.

## 2) Nest API on Render

1. In Render, **New → Blueprint** and connect this GitHub repo (or create a Web Service with Docker).
2. Use `render.yaml` at the repo root (dockerfile `apps/nest-api/Dockerfile`, context `.`).
3. Fill **sync: false** env vars in the dashboard:

| Variable | Example |
|----------|---------|
| `DATABASE_URL` | Neon pooled URL |
| `RESEND_API_KEY` | `re_...` from [Resend](https://resend.com) |
| `AUTH_EMAIL_FROM` | `Personal OS <noreply@your-domain.com>` |
| `WEB_APP_URL` | Base URL for links in auth emails (magic links); any HTTPS origin you own |
| `CORS_ORIGIN` | Browser origins allowed to call the API; the mobile app does not need one |
| `WEBAUTHN_RP_ID` | Passkey relying-party hostname; only needed once passkeys are used |
| `WEBAUTHN_ORIGIN` | Passkey origin, `https://` + the hostname above |

Blueprint already sets `COOKIE_SAME_SITE=none`, `TRUST_PROXY=true`, and generates `JWT_SECRET`, `AUTH_TOKEN_SECRET`, and `AI_SERVICE_TOKEN`.

4. Deploy and confirm health:

```bash
curl -sS https://<your-service>.onrender.com/api/v1/health
```

Migrations run on container start when `RUN_MIGRATIONS=true` (default in the Blueprint).

**Note:** Free Render services spin down when idle; the first request can take ~30s. AI assist still needs a hosted `apps/ai-api` (`AI_API_URL`) later — Nest will boot without it.

## 3) Landing page on Cloudflare Workers

`apps/web` is a static export (`out/`) served as Worker static assets, plus a small Worker for
launch-day sign-ups (`/api/notify`, Workers KV). It does not call Nest.

1. **Workers & Pages → Create → Workers → Import a repository**, this repo, branch `main`.
2. Root directory `apps/web`, build command `bun run build`, deploy command `npx wrangler deploy`.
3. Create a KV namespace and put its id in `apps/web/wrangler.jsonc` (`WAITLIST` binding).
4. Add a custom domain, for example `personalos.rabtx.dev`.

Full steps: `apps/web/README.md`.

## 4) Docs on Vercel

1. **Add another project** from the same repo.
2. **Root Directory:** `apps/docs`.
3. Env (optional, for docs AI chat):

| Variable | Value |
|----------|--------|
| `OPENROUTER_API_KEY` | from [OpenRouter](https://openrouter.ai) |
| `OPENROUTER_MODEL` | e.g. `anthropic/claude-3.5-sonnet` |

4. Deploy. Docs do not call Nest.

## Sessions and cookies

The mobile app sends `X-Client-Platform: native`, receives its refresh token in the response body
and stores it in SecureStore, so it needs no cookies and no CORS. Cookie settings
(`COOKIE_SAME_SITE`, `Secure`, `COOKIE_DOMAIN`) only matter for a browser client, and there is
none today: the landing page and docs never call the API.
