Run the backend stack with Docker Compose. Fragments live under **`docker/compose/`** and are merged by the root **`docker-compose.yml`** via [`include`](https://docs.docker.com/compose/how-tos/multiple-compose-files/include/) (Compose **v2.20+**). Compose files follow the Compose Spec (**no** top-level `version` key).

## Layout

| Fragment | Contents |
|----------|----------|
| `docker/compose/postgres.yml` | Postgres 16, named volume, healthcheck |
| `docker/compose/nest-api.yml` | NestJS API (multi-stage Bun image) |
| `docker/compose/ai-api.yml` | Optional FastAPI AI service (`--profile ai`) |

See **`docker/README.md`** for the manual `-f` fallback.

## Setup

1. **Copy env file** (from repo root):

   ```bash
   cp env.docker.example .env
   ```

   Set `JWT_SECRET` and `AUTH_TOKEN_SECRET` (32+ characters). Adjust ports if needed.

2. **Build and start the stack**:

   ```bash
   docker compose up -d --build
   ```

3. Open:

   - Nest health: http://localhost:4000/api/v1/health
   - Nest Swagger: http://localhost:4000/api/docs

## Ports

| Service | Host port (default) |
|---------|---------------------|
| Postgres | 5433 (container 5432) |
| Nest API | 4000 |
| AI API (profile) | 8000 |

## Notes

- Nest runs migrations on startup when `RUN_MIGRATIONS=true` (default).
- Host-only API development: `docker compose up -d postgres`, then `bun run dev`.
- Optional AI service: `docker compose --profile ai up -d --build`.
- The mobile app is not containerised; run it with Metro and a development build.
