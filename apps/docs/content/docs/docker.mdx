---
title: Local database
description: Postgres in Docker for the API and its tests; the API itself runs with Wrangler.
---
The API runs on Cloudflare Workers, locally through `wrangler dev`. Docker only provides Postgres.

## Start Postgres

From the repo root:

```bash
docker compose up -d
```

This starts Postgres 16 on host port **5433** with user and password `personal_os` and two
databases:

| Database | Used by |
|----------|---------|
| `personal_os` | `wrangler dev` (Hyperdrive's `localConnectionString` in `apps/api/wrangler.jsonc`) |
| `personal_os_api_test` | `bun --cwd=apps/api run test`, reset on every run |

The test database is created by `docker/postgres-init.sql` the first time the volume is created.
On an older volume, create it once:
`docker compose exec postgres createdb -U personal_os personal_os_api_test`.

## Run the API

```bash
cp apps/api/.dev.vars.example apps/api/.dev.vars   # local secrets, mock AI
bun --cwd=apps/api run db:migrate                   # apply migrations to personal_os
bun --cwd=apps/api run dev                          # http://localhost:4000/api/v1/health
```

On a phone, point the app at your computer's LAN address: `EXPO_PUBLIC_API_URL=http://<LAN IP>:4000`
in `apps/mobile/.env`.

## Notes

- Without `RESEND_API_KEY` in `.dev.vars`, sign-in codes come back in the response
  (`developmentCode`), so no inbox is needed locally.
- R2 is simulated by Wrangler locally. Presigned uploads need real R2 credentials; without them
  `POST /assets/uploads` answers `503 ASSETS_UNAVAILABLE`.
- The mobile app is not containerised; run it with Metro and a development build.
