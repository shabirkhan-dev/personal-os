## 1. System Vision & Architecture Principles

Personal OS is built as a secure modular monolith first, with event-driven seams and clear module boundaries, designed to scale into independent services when load or compliance requires it.

The core operational loop is:

```text
Action requested -> policy verification -> state transition in Postgres
-> outbox event -> background worker (notifications, audit, AI assist)
-> real-time sync to Web & Mobile clients
```

Engineering principles:
- **Relational Source of Truth:** PostgreSQL with Drizzle ORM holds all primary records.
- **Tenant Isolation:** Every multi-tenant operation is scoped by `organizationId` and `workspaceId`.
- **Stateless Application Servers:** API containers scale horizontally without local file or session state.
- **Defense in Depth:** Multi-factor authentication, passkeys (WebAuthn), CSRF protection, and strict Zod validation.

## 5. Data Model & Tenancy

### Tenancy and Access Control

| Table | Purpose | Key Attributes |
| --- | --- | --- |
| `organizations` | Top-level tenant account | `id`, `name`, `slug unique`, `status`, `createdAt` |
| `workspaces` | Project / environment boundary | `id`, `organization_id`, `name`, `slug`, `environment` |
| `users` | Global user identity | `id`, `email unique`, `status`, `password_hash` |
| `user_profiles` | Personal details and avatar | `id`, `user_id`, `display_name`, `avatar_url`, `locale` |
| `memberships` | User access to workspace | `id`, `workspace_id`, `user_id`, `status` |
| `roles` | Role definitions | `id`, `workspace_id nullable`, `code`, `name` |
| `permissions` | Granular permission catalog | `id`, `code unique`, `module`, `description` |
| `role_permissions` | Permissions assigned to roles | `role_id`, `permission_id` |
| `sessions` | Active user sessions | `id`, `user_id`, `token_hash`, `expires_at`, `ip`, `userAgent` |

## 6. Security & Authentication Architecture

1. **Password Authentication:**
   - Hashed using Argon2id with per-user salt.
2. **Session & Token Model:**
   - Short-lived JWT access tokens (15 minutes).
   - Long-lived secure, HTTP-only refresh cookies with rotation and revocation.
3. **Multi-Factor Authentication (MFA):**
   - RFC 6238 TOTP factors with encrypted secret storage.
   - Encrypted backup codes generated on factor activation.
4. **Passkeys (WebAuthn):**
   - FIDO2 / WebAuthn standard support.
   - Credential challenge verification stored with TTL.
5. **CSRF & Rate Limiting:**
   - Double-submit CSRF cookie guard on state-changing API endpoints.
   - In-memory / Redis token-bucket rate limiting on authentication routes.

## 7. Event Streams & Outbox Pattern

All critical events follow the outbox pattern inside database transactions to ensure consistency:

| Topic | Partition Key | Purpose |
| --- | --- | --- |
| `starter.workspace.events.v1` | `workspaceId` | Workspace creation, update, and quota telemetry |
| `starter.auth.events.v1` | `userId` | Login, password reset, MFA factor activation |
| `starter.notification.events.v1` | `recipientId` | Transactional emails, in-app alerts |
| `starter.audit.events.v1` | `workspaceId` | Immutable audit trail for compliance |
| `starter.ai.actions.v1` | `workspaceId` | Prompt telemetry, assist proposals, approval queue |

## 8. Deployment & Infrastructure

Deployment targets:

- **Local Development:** `docker-compose.yml` orchestrates PostgreSQL, the Nest API and the optional AI API.
- **Mobile:** EAS development, preview and production builds, plus EAS Update.
- **Production API:** NestJS container deployed on Render, Fly.io, or AWS ECS with pooled PostgreSQL (e.g. Neon).
- **Object Storage:** S3-compatible private buckets (Cloudflare R2, AWS S3) with pre-signed upload URLs.
