## 1. Project Vision

Starter is not another generic CRUD scaffold, digital form, or empty dashboard.

Starter is an **AI-native, policy-native, workflow-native platform and starter kit for modern multi-tenant applications**.

Traditional boilerplate software usually does this:

```txt
User enters data
System stores data
User checks dashboard manually
User takes action manually
```

Starter does this:

```txt
System understands workspace and tenant state
System detects anomalies, pending tasks, and policy violations
System creates guided tasks and reminders
AI drafts or assists the next action
Policy engine verifies allowed operations and quotas
Human approval is required for sensitive operations
System executes approved workflow
Audit log records everything
```

The long-term vision is a universal baseline for any SaaS or platform project—empowering developers to launch secure, compliant, multi-tenant products without reinventing the spine.

Build focus:

```txt
Start with Starter.
Build cleanly.
One production-quality vertical slice at a time.
```

## 3. Technical Decisions

### Runtime and Tooling

```txt
Package manager: Bun
Workspace orchestration: Turborepo
Main backend framework: NestJS
Production backend runtime: Node-compatible Nest build
Database: PostgreSQL
ORM/query layer: Drizzle ORM
Validation: Zod
API style first: REST
Frontend: Next.js
Mobile: Expo / React Native
AI Assist: FastAPI (apps/ai-api)
Performance service: Rust (apps/rust)
Docs: Fumadocs
```

Bun handles fast local development and monorepo tasks. NestJS provides the enterprise spine: dependency injection, guards, interceptors, queues, WebSockets, auth, testing, and modular separation.

Drizzle is TypeScript-first, lightweight, SQL-friendly, and optimal for PostgreSQL multi-tenancy.

## 6. Main Engines

These engines form the foundation of Starter. Feature modules plug directly into these engines.

### 6.1 Workflow Engine

Manages multi-step processes across workspaces.

Examples:

```txt
user onboarding workflow
access escalation workflow
resource provisioning workflow
billing downgrade remediation workflow
data export and cleanup workflow
```

A workflow has:

```txt
definition
run
steps
owner
status
deadline
approval
escalation
audit events
```

### 6.2 Policy Engine

Turns business and security rules into executable logic.

Examples:

```txt
If workspace quota exceeds 90% → create upgrade task
If member inactive for 90 days → trigger security review
If two-factor auth disabled on admin role → block access to production
If sensitive export requested → require second admin approval
```

### 6.3 Task Engine

Every actionable item becomes a trackable task.

Examples:

```txt
Review pending invite
Verify account credentials
Rotate API credentials
Resolve billing dispute
Review elevated access request
```

### 6.4 Notification Engine

Handles communication across channels:

```txt
in-app notifications
transactional email (Resend)
webhook dispatches
push notifications (Expo)
```

### 6.5 AI Orchestration Engine

AI assists human decisions rather than acting autonomously on sensitive state:

```txt
AI reads allowed context
AI proposes action or draft
Policy engine checks proposal
Permission engine checks authorization
Human approval occurs if required
Backend executes command
Audit log records everything
```

### 6.6 Document and Data Intelligence Engine

Used for data intake and ingestion:

```txt
file parsing and extraction
schema validation
document classification
form prefill
human verification
```

### 6.7 Integration Engine

Handles external services cleanly:

```txt
email provider (Resend)
payment gateways (Stripe / Razorpay)
object storage (S3 / Cloudflare R2)
webhook deliveries
OAuth providers (Google, GitHub)
```

### 6.8 Audit and Governance Engine

Every state-changing action is traceable:

```txt
who performed it (actor ID, role, session)
when (ISO timestamp)
which organization / workspace
what changed (structured diff)
why (reason, task ID, or policy)
from which IP / device / user-agent
whether AI was involved
whether human approval was given
```

## 9. Backend Engineering Rules

1. **Explicit Module Boundaries:** Controllers handle HTTP routing; services handle business logic; repositories handle data access.
2. **Strict Zod Validation:** All DTOs are validated with Zod via `ZodValidationPipe`.
3. **Tenant Isolation:** Every query involving tenant data must filter by `organizationId` and `workspaceId`.
4. **No Direct Secret Exposure:** Secrets never leak in API responses, logs, or client configs.
5. **Idempotency:** Webhook handlers and critical mutations accept idempotency keys.

## 10. Phased Roadmap

### Phase 0 — Clean Base Architecture & Health Checks (Completed)
- Clean NestJS baseline with structured modules
- Request ID middleware and global HTTP exception filter
- Health check endpoints (`/api/v1/health`)

### Phase 1 — Database Connection and Migrations (Completed)
- PostgreSQL database module with connection pooling
- Drizzle ORM schema and migration tooling
- Auth, users, profiles, and sessions schemas

### Phase 2 — Organization and Workspace Slice
- `OrganizationsModule` and `WorkspacesModule`
- CRUD for organizations and workspaces
- Workspace slug uniqueness and status lifecycle

### Phase 3 — Auth, Sessions, and Security (Completed)
- Password hashing (Argon2id)
- JWT access tokens and secure HTTP-only refresh cookies
- Multi-factor authentication (TOTP) and Passkeys (WebAuthn)
- Social auth (OAuth) and magic link login

### Phase 4 — Roles, Memberships, and Permissions
- RBAC and ABAC guardrails
- Role assignments per workspace
- Fine-grained permission decorators

### Phase 5 — Team Members & Invitations
- Workspace member invitation flows
- Accept/reject invite with token verification
- Member status lifecycle (active, pending, suspended)

### Phase 6 — Billing & Subscriptions (Completed)
- Stripe and Razorpay payment provider integrations
- Subscription checkout sessions and portal redirects
- Webhook signature verification and entitlement updates

### Phase 7 — Audit Logs & Security Trails
- Immutable audit log table and service
- Interceptor for automatic audit recording on mutating endpoints
- Structured diff logging and IP/user-agent capture

### Phase 8 — Task & Remediation Engine
- Task creation, assignment, and status transitions
- Due dates, priority levels, and notification triggers
- Automated task creation from system events

### Phase 9 — Policy & Guardrails Engine
- Policy definitions stored as structured rules
- Policy evaluation middleware on critical actions
- Human-in-the-loop approval triggers

### Phase 10 — Workflow Engine
- Multi-step state machine runner
- Step execution with timeout and retry capabilities
- Execution history with full audit trail

### Phase 11 — AI Assist Integration (Completed)
- AI client in NestJS proxying requests to `apps/ai-api`
- Prompt orchestration with role, context, and guardrails
- Secure token-based service authentication

### Phase 12 — Web Admin Console Integration (Completed)
- Modern Next.js admin dashboard
- Operational pulse strip, growth metrics, and member management
- Responsive sidebar, command search, and profile settings

### Phase 13 — Mobile App Integration (Completed)
- Expo Router mobile app with Uniwind styling
- Shared auth, profile, and navigation patterns
- Safe area compliance and mobile-first ergonomics

### Phase 14 — Observability & Production Hardening
- Docker Compose local stack and multi-stage container builds
- Render / Vercel deployment blueprints
- Rate limiting, CSRF protection, and security headers
