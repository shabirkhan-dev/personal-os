The engineering roadmap for Personal OS. The board in `.agents/board/` tracks individual cards;
this page is the summary. Architecture context: [Product System Design](/docs/product-system-design).

## Built

### Foundation

- Bun + Turborepo monorepo, oxlint/oxfmt, Lefthook hooks, architecture and naming checks, CI,
  CodeQL and Dependabot.
- `@personal-os/tokens`: Figma Kit v2 colours, spacing, radii and text styles, light and dark.

### Mobile app

- Onboarding end to end: voice input, saved progress, reminders, plan reveal and sign-in.
- Today: Overview plus module Homes for Finance, Workout, Skincare and Food (with Recipes), and
  Profile, all on what the person enters. Module data is stored on the phone
  ([ADR 0001](/docs/architecture/adr-0001-on-device-module-data)).
- Ask bar that parses typed lines into module entries.
- Career module: pipeline, follow-ups with AI-drafted nudges, job links read by AI with a halal
  reading, interview prep with flashcards, and a 30-minute-a-day skill path.
- Faith module: prayer times on the phone (location or typed times) with reminders, a Sky header
  that follows the time of day, prayer logging and consistency, Qibla compass, Tasbih, Quran
  recitation timer, ayah and dua cards read aloud, Zakat, Grow (challenges, paths, flashcards,
  notes) and Insights, plus questions answered by the Faith AI.
- Voice in and out on the phone behind one swappable layer (`src/lib/voice`), and Talk to OS
  (`personalos://listen`), which opens listening and hands the line to the right module.
- Long AI work runs in the background with a working card, so no screen waits on it.
- Offline-first record store on the phone with sync to the API
  ([ADR 0002](/docs/architecture/adr-0002-offline-first-sync)).
- EAS development builds, EAS Update channels and a one-command APK build.

### API and services

- One Hono API on Cloudflare Workers ([ADR 0003](/docs/architecture/adr-0003-one-api-on-workers)):
  Neon through Hyperdrive, Cloudflare rate limiting, typed config and one table of error codes.
- Email-code sign-in with rotating refresh sessions.
- Profile with avatars uploaded straight to R2; onboarding answers stored and synced.
- Career AI inside the API, with a mock provider for development and tests.
- Landing page on Cloudflare Workers with a launch waitlist.

## Next

Roughly in order; each item becomes board cards.

1. **Remaining modules**: Daily life and Fashion, on the record store.
1. **"Hey OS" wake phrase**: an on-device wake word in an Android foreground service (iOS does not
   allow always-on listening), opening Talk to OS.
2. **Move Finance, Workout, Skincare and Food onto the record store** so everything is synced.
3. **Files**: an avatar picker and photos through the R2 upload flow; videos streamed from Google
   Drive.
4. **Insights**: AI over a per-module, opt-in daily digest, shown in the Insights tab.
5. **Production hardening**: error tracking, migrations in the deploy pipeline, and real deploy
   steps in `cd.yml` (it is still a template).
6. **Desktop app** on the same record store and sync.

## Engineering rules

- Every API change updates [Backend API](/docs/backend-api) in the same commit.
- Schema changes ship with a generated migration; no schema push outside local development.
- Pure logic gets unit tests; screens handle loading, empty and error states.
- No secrets in the app bundle; provider keys are Worker secrets.
- `bun run preflight` passes before a push.
