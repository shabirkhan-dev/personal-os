This roadmap separates what is shipped from what is planned. It is intentionally incremental:
stabilize one useful life loop, make it trustworthy, then add the next domain.

## Product direction

Personal OS helps one person capture the things that shape a day—routines, spending, personal care,
food, and fashion—and see them together without turning life into a noisy dashboard.

The core loop is:

```text
Plan or capture a moment → persist it safely → see today's state → learn over time → take the next action
```

The product is not a school ERP, a social network, or a shared multi-tenant admin system. It is a
personal-first system with a web surface, a mobile-first logging surface, and an assistive AI layer.

## Current baseline

The platform foundation is in place:

- Bun workspaces and Turborepo task orchestration.
- Next.js web and Expo Router mobile clients.
- NestJS modular API with Drizzle and PostgreSQL.
- Fumadocs engineering handbook and API status board.
- Auth spine: sessions, passkeys, MFA, social sign-in, profiles, and billing adapters.
- Docker Compose, CI, Lefthook, Biome, architecture checks, and a Dev Container.
- Internal `apps/ai-api` service behind the Nest AI proxy.

The live API surface is tracked in [Backend API](/docs/backend-api). Treat its status table as more
current than any planning prose.

## Milestones

### M1 — Identity and daily routines

Status: API ready; clients and polish continue.

- Auth and profile onboarding.
- Daily and weekly routine CRUD.
- Ordered routine items and per-day completion state.
- Today view that respects the user's timezone.
- Mobile-first logging and reminder foundations.

### M2 — Personal finance

Status: API ready; product surface continues to mature.

- Transactions with categories and notes.
- Budgets and month summaries.
- Safe correction and deletion behavior.
- Clear empty, loading, and error states in web and mobile.

### M3 — Personal care and food

Status: planned.

- Skincare, grooming, and wellness routines built on the same routine primitives.
- Meals, planning, preferences, and lightweight nutrition context.
- Shared timeline events without forcing unrelated domains into one schema.

### M4 — Fashion

Status: planned.

- Wardrobe inventory, outfits, and style notes.

### M5 — Personal OS Intelligence

Status: planned — the first implementation program is tracked on the coordination board.

Personal OS Intelligence is the product's AI control layer with two equal entry points:

- **Daily Intelligence:** proactive, explainable insights about routines, spending, goals, and
  current state.
- **Personal OS Chat:** context-aware conversation that understands screens, records, dates,
  projects, and prior decisions.

The initial release is read-only so the product can earn trust quickly. It must answer from the
user's authorized Personal OS context, show which context it used, and never pretend that a write
was completed. Confirmed actions, project creation, long-term memory, and automations follow as
separate milestones.

#### Intelligence delivery sequence

1. **Foundation:** define AI context, insight, session, message, and suggested-action contracts.
   Nest remains the public auth, authorization, rate-limit, and audit boundary; the internal AI
   API remains provider/model-specific.
2. **Daily Intelligence v0:** generate a small number of high-signal routine and finance insights
   with source references, priority, explanation, and a useful next step.
3. **Personal OS Chat v0:** provide mobile and web chat with screen/entity/date context, history,
   loading/error/retry states, and context chips. Chat is a command center, not a blank chatbot.
4. **Confirmed actions:** allow typed action intents such as creating a routine or project only
   after a structured preview, explicit confirmation, idempotent execution, and an audit entry.
5. **Memory and projects:** add user-approved preferences, decisions, project spaces, and durable
   references. Users must be able to inspect, correct, export, and delete memory.
6. **Proactive automations:** let users opt into bounded recurring agents with schedules,
   permissions, rate limits, failure notifications, and complete activity history.

The north-star loop is:

```text
Observe authorized state → understand context → explain insight → propose action
→ confirm when needed → execute through typed tools → record outcome → learn with permission
```

The product may eventually cover general research and external tools, but the first wedge is a
trusted assistant for the user's own life. Provider keys remain server-side and model output is
untrusted until validated.

## Engineering sequence

1. **Stabilize contracts.** Keep the `/api/v1` envelope, auth semantics, timezone rules, and
   pagination/date conventions consistent.
2. **Complete the daily loop.** Make routines fast, forgiving, and useful on mobile before adding
   more domains.
3. **Add domain modules inside Nest.** Keep one database and one deployable API while boundaries are
   still changing.
4. **Instrument trust.** Add auditability, idempotency, rate limits, and useful operational metrics
   before automation becomes important.
5. **Introduce AI carefully.** Start with the M5 read-only vertical slice. Nest remains the policy
   boundary; the internal AI service handles provider-specific work and can be replaced without
   changing clients.
6. **Add actions only after trust.** Every AI write needs typed tool validation, ownership checks,
   confirmation policy, idempotency, auditability, and undo or correction behavior.
7. **Split only with evidence.** A service boundary needs a measured workload, independent ownership,
   or a concrete reliability/security reason.

## Definition of done for a product slice

- The API contract is documented and versioned.
- Web and mobile callers agree on loading, empty, error, and auth-refresh behavior.
- Timezone, ownership, validation, and authorization cases have tests.
- The design works at mobile and desktop widths where applicable.
- Logs contain enough context to diagnose a failed action without secrets or personal data leaks.
- The source-of-truth docs and `.agents/` hand-off are updated.
