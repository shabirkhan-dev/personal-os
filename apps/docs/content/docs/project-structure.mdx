## Where to put new code

| Need | Location | Rule |
| --- | --- | --- |
| Browser route or feature | `apps/web/src/` | Keep routing, feature UI, and app helpers inside the web app |
| Mobile route or feature | `apps/mobile/src/` | Use `src/app` for routes and `src/components` for reusable UI |
| API module or endpoint | `apps/nest-api/src/modules/` | Keep controllers thin; update the API doc in the same change |
| AI provider or prompt flow | `apps/ai-api/` | Reach it through Nest; do not expose provider keys to clients |
| Shared web primitive | `packages/ui/src/` | Keep it app-agnostic and expose a public package entrypoint |
| Documentation | `apps/docs/content/docs/` | Add the page to the nearest `meta.json` |
| Cross-team request | `.agents/board/open/` | Use the board protocol; do not edit another team's notes |

Product direction and milestones live in `apps/docs/content/docs/production-roadmap.mdx`. The
existing shared package names use the `@school-os/*` npm scope from the original starter. Keep
those imports working until the package namespace is intentionally migrated; do not introduce a
second alias casually.

## Boundaries that matter

- Apps may depend on shared packages, but apps must not import one another through relative paths.
- Packages must not import app aliases such as `@/...`.
- Web modules should be consumed through their public module boundary, not deep internal files.
- API contracts belong in `apps/docs/content/docs/backend-api.mdx`; cards and notes should link there.
- Run `bun run architecture:check` when moving files or introducing a new package boundary.
