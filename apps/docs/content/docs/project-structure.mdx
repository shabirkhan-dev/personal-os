## Repository layout

```text
personal-os/
├── apps/
│   ├── mobile/        # The Expo app
│   ├── api/           # Hono API on Cloudflare Workers
│   ├── docs/          # Fumadocs site; MDX in apps/docs/content/docs/
│   └── web/           # Landing page, Cloudflare Workers
├── packages/
│   ├── tokens/        # @personal-os/tokens
│   └── typescript-config/  # @personal-os/typescript-config
├── scripts/           # git hooks, architecture and naming checks
├── docker/          # Postgres init script for docker-compose.yml
├── turbo.json
└── .oxlintrc.json
```

## Core principles

- Keep app-specific code inside each app folder.
- Move reusable logic into `packages/*`.
- Prefer workspace imports (`@personal-os/tokens`) over copy-paste.
- Keep tooling centralized at repository root.

## Where to add new code

- New feature in the app: `apps/mobile/src/modules/<feature>`
- New API feature: `apps/api/src/modules/<feature>` (routes, service, repository, schema)
- New product surface: `apps/<new-app>`
- Shared UI/utilities/types: `packages/<new-package>`
- Docs pages: `apps/docs/content/docs/` (served at `/docs/...`)
- Automation scripts: `scripts/`

## Why this works

Each app evolves on its own while lint, format, typecheck and the architecture checks stay the
same across the repo.
